# 언제 쓰는지

배분기준표 CSV를 읽는 소관 과 추천 엔진의 1순위 정확도가 목표에 못 미쳐 규칙을 보강할 때 사용한다. 조직도 26개 과, 배분기준표, 시험 40건, 과거 접수대장 520건이 있는 작업에 적용한다.

# 순서

1. 원본 배분기준표와 조직도, 시험 40건, 접수대장 520건을 읽고 현재 1순위·3순위 정확도를 측정한다.
2. 1순위 오답을 일반 키워드와 전문 키워드의 충돌, 제외어 부족, 키워드 누락, 우선순위 충돌 등 원인별로 묶고 원인마다 `제외어 추가`, `키워드 추가`, `우선순위 변경` 중 한 가지 보강안을 제안한다. 예상 변경을 메모리에서 먼저 모의 평가한다.
3. 제안만 보여 주고 사용자가 선택할 때까지 원본과 사본을 수정하지 않는다. 사용자가 고른 규칙·값·방법을 정확히 확인한다.
4. 원본 배분기준표를 보존한 채 `rules_보강.csv` 사본을 만들고, 사용자가 고른 변경만 반영한다. 변경 과가 조직도 26개 과 안에 있는지와 변경 규칙 수를 확인한다.
5. 같은 채점 방식으로 시험 40건과 접수대장 520건을 다시 평가한다. 변경 전·후 1순위, 시험 3순위 안, 새로 틀린 문항 수를 표로 비교하고 변경 규칙과 결과를 `PROGRESS.md`에 기록한다.

# 끝나는 조건

- 원본 배분기준표는 바뀌지 않고 `rules_보강.csv`에 선택한 변경만 있다.
- 변경 전·후 시험 40건과 접수대장 520건의 1순위 정확도가 같은 기준으로 계산됐다.
- 시험 40건의 변경 후 1순위가 30건 이상이고, 변경 전에는 맞았으나 변경 후 새로 틀린 문항이 0건이다.
- 조직도 밖 과가 새 규칙이나 결과 후보에 없다.
- 변경 규칙, 정확도 표, 남은 오답과 막힌 점이 `PROGRESS.md`에 기록됐다.

# 하지 말 것

- 배분 규칙을 엔진 코드에 하드코딩하지 않는다.
- 사용자가 고르지 않은 제안이나 값은 `rules_보강.csv`에 넣지 않는다.
- 원본 배분기준표, 조직도, 시험 정답, 접수대장을 수정·삭제·이동하지 않는다.
- 정확도를 높이려고 시험 정답이나 과거 접수 결과를 키워드 규칙으로 복사하지 않는다.
- 조직도에 없는 과를 만들거나 추천하지 않는다.
- 변경 후 정확도만 제시하고 변경 전 수치나 새로 틀린 문항 검사를 생략하지 않는다.
